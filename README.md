# PhoneAgent v0.2.3:定位"创建不了 IOSurface"的原因

本版一次编出两个 .tipa,用来做对比:
- PhoneAgent.tipa    完整权限(去沙盒),端口 8200
- PhoneAgent-SB.tipa 保留沙盒(桌面名 PA-SB),端口 8201

## 测试
1. 两个都用 TrollStore 安装。
2. 一次只开一个(另一个先在多任务里划掉,因为后台保活会让它一直活着)。
3. 每个 App 打开后,日志里会有 [诊断] 段落,也可以点"诊断 IOSurface"重看。
4. 再点"3 秒后 截屏 + OCR",切到设置等 3 秒,回来看结果。
5. 点"3 秒后点击"测试触摸还能不能用。

## v0.2.4 截图修复尝试

- 截图顺序调整为 B → C → D → A，避免方法 A 返回无效纯色图后提前结束。
- 每种方法返回图片后，都会进行 32×32 像素抽样检测；近似纯色图会被判为失败并继续尝试下一种方法。
- 若所有方法都失败，界面会显示每种方法的失败原因。
- 本次修改没有改变触摸注入、后台保活和 HTTP 接口协议。

注意：这是针对“方法 A 返回蓝色纯色图”的诊断性修复版本，尚未在你的 iPhone 真机编译运行验证。若 B/C/D 仍无法取得真实画面，日志会帮助继续定位 CARenderServer 或系统权限问题。

## v0.2.5 增加方法 E：_UICreateScreenUIImage

- 新增方法 E：通过 dlsym 查找 UIKit 私有函数 `_UICreateScreenUIImage()`，让系统内部完成截图，不再自己创建 IOSurface 再调渲染服务。
- 截图顺序改为 E → B → C → D → A，E 优先尝试；每种方法同样过纯色图检测，纯色图判失败后继续试下一种。
- 如果 iOS 16 上已经没有这个符号，日志会写“没有 _UICreateScreenUIImage 符号”，自动继续试 B/C/D/A，不影响其他功能。
- 本次修改没有改变触摸注入、后台保活和 HTTP 接口协议。
